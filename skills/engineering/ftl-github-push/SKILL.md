# GitHub 安全推送

把一次明确的 GitHub 推送做成可审查、可停止、可验证的发布动作。先证明将要推送什么和推到哪里，再执行普通快进推送；不能用“自动化”代替用户授权或项目规则。

## 面向用户的表达

在产生本次任务的面向用户聊天文本前，完整读取并使用 `ftl-soul`；其适用范围和正式产物例外以该 Skill 为准。

## 进入条件

- 只有用户当前请求明确要求推送、发布或更新 GitHub 时才执行外部写入。过去的推送、完成本地修改、创建 commit 或需求确认都不构成本次授权。
- 自然语言中的明确推送要求可以自动触发本 Skill，也可以显式调用 `$ftl-github-push`。普通 Git 状态查询、本地提交、隐私讨论或其他托管平台请求不使用本 Skill。
- 用户只说“推送”时只处理已经存在的提交；未提交和未跟踪内容不纳入推送，并在结果中明确提醒。用户明确要求“提交并推送”时，先把提交部分交给目标项目实际适用的工作流，提交和验证完成后再返回本 Skill。

## 保留项目治理

先读取目标项目范围内的 `AGENTS.md` 和真实入口，遵守其分支、验证、发布与提交规则。本 Skill 只负责发布前审查、推送授权、普通推送和远端核验；不得绕过项目工作流形成提交，也不得把项目没有声明的 FTLSoul 生命周期强加给目标项目。

## 锁定推送目标

从可靠 Git 状态确定仓库根目录、当前分支、HEAD、工作区、远端、upstream、推送 URL 和目标分支。只在这些信息能够唯一确定时继续：

- detached HEAD、多个同等候选远端、目标分支含义不明、推送 URL 不是 GitHub 或 URL 内嵌凭据时停止，不猜测。
- 普通更新优先使用当前分支已经配置的 upstream；没有 upstream 但只有一个明确 GitHub 远端时，可以把当前分支作为候选目标并向用户说明。多个候选必须由用户选择。
- 首次发布必须由用户明确给出或确认精确 GitHub 仓库、目标分支和可见性。不得擅自创建仓库、设置或更换远端、改变可见性或初始化远端内容。
- 通过 `git ls-remote --heads` 读取真实远端分支 SHA，再把该精确分支获取到本地远端跟踪引用。不要使用会顺手更新其他分支或标签的宽泛获取方式。

## 只读审查

从当前 Skill 目录运行 `scripts/inspect-github-push.ps1`，传入仓库根目录、远端名和目标分支；首次发布额外使用 `-InitialPublication`。脚本只读取本地 Git 状态并输出 JSON，不联网、不暂存、不提交、不修改远端。必须先完成上节的远端查询与精确 fetch，不能把陈旧跟踪引用当作真实远端。

`-AllowNonGitHubRemoteForTest` 只供本 Skill 自带的隔离测试脚本连接本地 bare remote；真实任务禁止使用它绕过 GitHub 目标校验。

审查报告至少确认：

- 本地与远端是本地领先、完全同步、远端领先还是双方分叉；只有本地领先的普通更新或已经确认的首次发布可以继续。
- 待推送提交、作者邮箱、涉及文件、历史中新引入的对象、异常大文件和二进制产物。
- 工作区是否还有未提交或未跟踪内容；这些内容不会因推送已有提交而上云。
- 高可信令牌、密码、私钥、认证文件和凭据配置，以及个人邮箱、本机用户名、绝对路径、内部地址和私有说明等上下文隐私。

脚本的 `blocker` 必须阻止推送。高可信凭据或认证材料只报告风险类型和文件路径，不回显匹配值，也不能被一句笼统的“隐私无所谓”整体放行；先由目标项目工作流移除秘密并重新形成提交，已经进入公开历史时还要提醒用户轮换凭据并单独处理历史。

脚本的 `warning` 必须逐项告诉用户。普通本机路径、用户名、邮箱、内部说明、大文件或可疑二进制由用户明确接受后可以继续；没有警告且目标、范围唯一时，用户当前的明确推送请求已经构成本次普通推送授权，不重复确认。

扫描只降低误传风险，不能宣称证明仓库绝对没有秘密。报告显示扫描不完整、检查工具失败或首次公开历史无法可靠覆盖时停止高风险公开发布。

## 远端漂移保护与推送

在审查开始时记录本地 HEAD 和远端分支 SHA。所有警告已经得到精确接受后，按以下不变量执行：

1. 再次用 `git ls-remote --heads` 查询同一远端分支；结果必须与审查基线完全一致，首次发布则仍必须不存在该分支。
2. 本地 HEAD 必须仍是审查过的提交，工作区变化可以保留但必须重新说明不会被推送；提交图、目标或隐私范围变化时重新审查。
3. 先对精确 refspec `HEAD:refs/heads/<目标分支>` 执行 `git push --dry-run`。预演失败就停止。
4. 执行一次不带强制参数的同一精确 refspec 普通推送。遵守 pre-push hook 和分支保护，不使用 `--force`、`--force-with-lease`、`--mirror`、`--all`、`--tags` 或 `--no-verify`。
5. 推送后再次读取远端目标分支 SHA，并与审查过的本地 HEAD 比较。只有二者完全一致才报告成功。

普通推送遇到远端领先或分叉时，不自动 pull、merge、rebase、reset、改写历史或更换远端。网络、认证、权限、hook、分支保护和服务器拒绝都保留真实错误并停止；需要用户登录或扩大权限时明确说明，不尝试复制、输出或记录凭据。

## 完成说明

成功后简洁报告远端仓库、源分支、目标分支、推送提交范围、最终 SHA、隐私警告的处理结果以及仍留在本地的未提交内容。没有待推送提交时报告已经同步，不执行空洞的写入，也不声称未提交文件已经上云。

## 禁止扩大

本 Skill 不创建、删除、转移或重命名仓库，不修改可见性、默认分支、保护规则、协作者、Actions、Secrets、Pages、Issues、PR、Release 或账号设置；不删除远端分支或标签，不自动提交、暂存、清理或丢弃用户文件。任何超出“把审查过的本地提交普通推送到已确认 GitHub 分支”的动作都需要新的明确授权和适用工作流。
