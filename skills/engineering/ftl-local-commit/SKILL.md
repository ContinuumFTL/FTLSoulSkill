# 本地安全提交

接收上游业务 Skill 已经决定的提交单元，安全创建一个可独立理解、审查和回退的本地 Git commit。本 Skill 只负责提交机制，不把存在 commit 解释为业务流程完成，也不自行扩大提交范围。

## 提交上下文

开始前确认上游已经给出：

- 本次提交的目的和结果语义；
- 允许暂存的精确路径；
- 必须通过的验证及其真实结果；
- 本次提交在上游流程中的性质，例如文档确认、实现检查点或完成状态。

缺少会改变提交边界或业务含义的信息时，返回上游业务 Skill 处理，不自行推断。

## 初始化缺失的仓库

目标目录不是 Git 工作树时：

- 先根据上游任务和项目规则确认该目录是预期项目根目录，并确认它不位于另一 Git 工作树内；无法可靠确认时停止，不创建嵌套仓库。
- 确认根目录后初始化本地 Git 仓库；不配置远端，不执行 push，也不引入其他外部副作用。
- 创建业务提交前先建立安全的初始基线；检查忽略规则、候选文件、敏感信息、生成物和本地数据，任何不应纳入版本控制的内容都不得进入基线。
- 初始基线是独立提交单元。基线所需路径超出上游授权范围时，返回上游补充基线的提交目的、精确路径和验证条件，不擅自扩大业务提交范围。
- 无法安全建立基线、发现疑似秘密或项目规则禁止初始化时，保留现有文件并停止提交，如实返回原因。

## 创建提交

- 遵循用户和项目规则对提交的明确限制，并确认 Git 命令可用；需要时先按上述规则完成仓库初始化和初始基线。
- 检查工作树、暂存区和现有差异，识别用户或其他任务的既有改动；不覆盖、回滚或临时隐藏这些改动。
- 只暂存上游允许的明确路径。若同一路径内混有无法安全分离的既有改动，不创建提交。
- 提交前检查 staged 文件列表和 staged diff，确认内容只属于本提交单元，并与提交目的相符。
- 只有上游要求的验证已经通过、结果不是临时状态且暂存内容非空时，才创建描述该结果的本地 commit。
- 创建后核对提交结果，将真实 commit 标识和工作树状态返回上游。

## 无法提交

Git 命令不可用、仓库初始化或安全基线无法完成、项目规则禁止提交、验证未通过、没有可提交内容或改动无法安全隔离时，不创建 commit。保留能够安全保留的工作，并如实返回原因和当前状态。

本地 commit 不授权 push、合并、创建 PR、部署、发布、改写历史、额外删除或发送外部消息；这些动作需要各自独立的明确授权。
