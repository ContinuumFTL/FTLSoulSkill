# Codex 沙箱认证恢复

这是一个已知的 Windows 安全身份隔离问题，不是需要重新调查的未知登录故障：普通终端中的 Codex 已登录，但 `CodexSandboxOffline` 等 Agent 沙箱身份无法访问普通用户的系统凭据，因此同一个 CLI 会在沙箱中报告 `Not logged in`。

正确修复是让真正需要登录凭据的 Codex CLI、App Server 及其父级项目命令运行在已登录的宿主用户上下文。不要在沙箱中重新登录，也不要搬运凭据。

## 面向用户的表达

在产生本次任务的面向用户聊天文本前，完整读取并使用 `ftl-soul`；其适用范围和正式产物例外以该 Skill 为准。先直接说明：“你的 Codex 和登录没有坏；当前命令只是运行在拿不到宿主凭据的沙箱身份中。我会改用已登录的宿主用户上下文执行。”

## 最低适用条件

满足以下已知特征时直接使用恢复路线，不再枚举全部 CLI、PATH、配置和凭据元数据：

- 普通 Windows 终端中的目标 Codex CLI 已明确报告已登录；
- Agent 沙箱或由它启动的项目进程对同一目标 CLI 报告 `Not logged in` 或要求设备码；
- 两边使用同一套安装，或者只有 `codex.ps1`、`codex.cmd`、无扩展包装器等同一 npm 安装的入口差异。

若缺少“宿主已登录”这一条证据，只在宿主上下文执行一次不调用模型的最短前置检查，不展开完整诊断：

```powershell
(Get-Command codex).Source; codex --version; codex login status; whoami
```

宿主也报告未登录时，本 Skill 不适用；告诉用户必须在目标 CLI 的普通终端亲自登录，不得由 Agent 发起认证。宿主和沙箱实际命中不同安装时，先由项目显式选择正确 CLI；这不是凭据隔离修复。

## 立即恢复

1. 保持用户日常使用且已经登录的 CLI，不修改 `PATH`、`USERPROFILE`、`CODEX_HOME`、凭据存储配置或登录状态。
2. 找到真正会启动 Codex CLI 或 App Server 的最外层项目命令。验收脚本、Python 进程或测试运行器会把自己的 Windows 安全身份传给子进程，因此必须让整个父命令运行在宿主上下文；只给内部 `codex.exe` 换路径没有用。
3. 在 Codex 桌面 Agent 中，为该明确命令请求一次范围精确的宿主上下文执行批准，例如使用执行工具的 `sandbox_permissions: "require_escalated"`，并在批准理由中说明它要使用用户现有的 Codex 登录。不得把批准请求伪装成登录、安装或泛化的管理员权限。
4. 在同一宿主上下文先执行上面的最短前置检查。它必须显示预期 CLI、已登录状态和普通用户身份；该检查不启动 App Server、不调用模型、不消耗模型额度。
5. 前置检查通过后，执行用户原本已经授权的项目父命令。若该命令会调用模型，仍以用户对原任务的授权和额度边界为准；认证恢复本身不构成模型调用授权。
6. 宿主执行能力不可用或用户拒绝批准时，不尝试其他凭据技巧。只给用户一条可在日常已登录终端运行的最短项目命令，并说明这是同一恢复路线的手动入口。

## 长期项目修复

用户要求永久修复项目时，携带下面的确定结论回到 `ftl-router`，按项目实际工作流实施，不再重新诊断原因：

- 把“CLI 绝对路径”和“启动 CLI 的 Windows 安全身份”设计成两个独立维度；显式路径只能解决选错 CLI，不能解决凭据隔离。
- 为需要账号凭据的验收或 App Server 提供清晰的宿主入口，让最外层命令在普通用户上下文启动。
- 检测到 `CodexSandboxOffline` 等隔离身份时快速失败，明确提示改用宿主入口；禁止自动转入登录或设备码流程。
- 启动前记录实际安全身份和最终 CLI 绝对路径，方便验证父进程没有再次落回沙箱。

## 禁止的伪修复

- 不执行或建议在沙箱中执行 `codex login`、`codex logout` 或设备码授权；
- 不读取、展示、复制或迁移 `auth.json`，不导出系统凭据；
- 不通过设置相同的 `USERPROFILE` 或 `CODEX_HOME` 冒充相同安全身份；
- 不把同一安装中的 `codex.ps1` 与 `codex.cmd` 当成两套 CLI；
- 不只把内部 Codex 子进程改为宿主执行，而把真正的父级验收进程留在沙箱；
- 不因认证恢复自动扩大为模型调用、项目修改、安装或其他外部操作授权。

## 验收

恢复完成必须同时满足：

- 实际项目父命令运行在普通宿主用户身份，而不是 `CodexSandboxOffline`；
- 父命令最终解析到预期 Codex CLI；
- 同一运行上下文中的 `codex login status` 报告已登录；
- 没有新增登录、设备码授权、凭据复制或凭据配置修改；
- 只有用户已经授权的实际项目动作被继续执行。
