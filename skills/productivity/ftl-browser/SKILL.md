# 内置浏览器优先

为已经获得授权的业务任务选择网页交互路径。这里只决定使用连接器、API、CLI 还是浏览器，以及浏览器表面的选择；不替代任务分类、需求流程、外部写入授权或危险操作确认。

## 面向用户的表达

在产生本次任务的面向用户聊天文本前，完整读取并使用 `ftl-soul`；其适用范围和正式产物例外以该 Skill 为准。

## 判断是否需要浏览器

- 用户明确要求打开、展示、导航、检查或操作网页 UI 时，保留浏览器意图。
- 用户要对仓库、账号、工单等资源执行语义操作，但没有要求操作网页时，先查找可用的专用连接器、API 或 CLI；它们能够完成当前操作时使用它们，不为使用浏览器而使用浏览器。
- 普通网络搜索、资料检索和无需交互页面即可完成的只读研究不使用本 Skill。
- URL、已经打开的标签页或此前使用过浏览器只是上下文，不会把后续语义操作自动变成浏览器优先。

## 选择浏览器表面

确需网页交互且用户没有明确指定系统浏览器时，完整读取并使用 `browser:control-in-app-browser`，直接选择其 Codex 内置浏览器绑定；不要让 URL 自动选择 Chrome、Edge 或其他系统浏览器。用户明确指定系统浏览器时，改用该浏览器实际适用的控制能力，不先连接内置浏览器。

- 除非用户在当前请求中明确指定 Chrome、Edge 或其他系统浏览器，否则只使用 Codex 内置浏览器。
- 用户明确指定系统浏览器时遵循该选择，但只对当前任务有效。
- 内置浏览器不可用、未连接或不能完成任务时，说明失败和可选路径并等待用户决定；不得静默改用系统浏览器、计算机控制或另一套自动化服务。
- 同一任务保持一个浏览器绑定和一条标签路径。复用仍有效的绑定；标签失效时在同一内置浏览器中重新取得或创建标签，不因标签丢失而切换浏览器。

## 登录与设备授权

- 同一登录或设备授权流程只打开一个页面，不同时在 Codex 内置浏览器和系统浏览器中打开同一 URL。
- CLI 显示设备码并询问是否打开系统默认浏览器时，若授权 URL 已知，保留 CLI 等待会话但不触发默认浏览器；只在 Codex 内置浏览器打开授权 URL，把一次性设备码交给用户输入。
- 若第三方程序无法抑制地自动打开系统浏览器，不再补开 Codex 内置浏览器。说明页面已经交给用户手动完成；只有用户决定终止外部流程并改走内置浏览器后才能切换。
- 可以展示当前流程生成、仅用于本次交接的一次性设备码；不得读取、索取、复制或转述用户密码、邮箱验证码、会话 Cookie、浏览器存储或其他登录凭据。

## 操作、超时与切换

- 使用选中浏览器的可见页面状态和专用控制能力执行操作；不要再通过系统命令或第二种浏览器打开同一页面作为“保险”。
- 控制调用超时但页面可能已经变化时，先检查同一浏览器的标签页、可见状态或目标资源的权威只读接口，判断动作是否已生效；没有证据前不重复点击会产生副作用的控件。
- 必须切换浏览器时先说明当前路径的真实失败、拟切换目标和登录状态影响，取得用户决定后再切换。不得把 VPN、登录或页面加载问题未经证据归因成浏览器故障。

## 授权边界

本 Skill 不因能够操作网页而授权创建、修改、发布、购买、发送消息、删除或其他外部副作用。每项动作仍受用户当前请求和适用业务工作流约束；永久删除、提交、支付等不可逆或高风险动作仍须在最后执行点完成相称确认。
