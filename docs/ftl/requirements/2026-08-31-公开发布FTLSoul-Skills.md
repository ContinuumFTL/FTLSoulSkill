## 目标

把当前本地 Git 仓库以真正允许复用的开源项目发布到 GitHub 公共仓库
`ContinuumFTL/FTLSoulSkill`。首次公开前补充许可证并清理当前版本中的本机绝对路径，完整保留
现有 Git 历史和回滚点，并让本地 `main`、远程 `main` 和公开页面保持一致。

## 已确认选择

- 远程仓库归属为 `ContinuumFTL`，仓库名为 `FTLSoulSkill`，可见性为 Public。
- 远程仓库创建时不由 GitHub 初始化 README、`.gitignore` 或许可证，避免产生无关的独立历史。
- 项目采用 Apache License 2.0；标准许可证文件由本地仓库添加后随正式历史一起推送。
- 不改写现有 Git 历史，保留全部提交哈希、内部提交引用和本地回滚能力；接受旧提交元数据中
  `continumftl@gmail.com`、旧版本文件中的本机用户名和本地路径会随公开历史可见。
- 上述历史信息不包含已发现的令牌、API Key、私钥或密码；是否保留属于隐私取舍，而非已知
  凭据泄露。
- 从下一次提交开始，提交作者和提交者名称保持 `ContinuumFTL`，邮箱使用 GitHub 隐私邮箱
  `126903866+ContinuumFTL@users.noreply.github.com`。
- 当前版本中含本机用户名的 Windows 用户目录改为 `%USERPROFILE%` 形式，特定盘符的本地仓库
  绝对路径改为 `<仓库根目录>` 等不绑定具体机器的表达；只创建前向清理提交。

## 实施范围

1. 将本仓库今后的 Git 作者邮箱配置为已确认的 GitHub 隐私邮箱，不修改既有提交。
2. 在当前版本中清理含本机用户名的用户目录和特定盘符的本地仓库绝对路径，不改变相关文档的
   事实含义，也不改写 Git 历史。
3. 添加标准 Apache License 2.0 根目录许可证，并在 README 中简洁声明许可证。
4. 以普通前向提交记录路径清理和许可证变更，保留全部现有提交哈希与内部提交引用。
5. 只在全部本地验证通过后设置 `origin` 为
   `https://github.com/ContinuumFTL/FTLSoulSkill.git`，把当前 `main` 首次推送到空的公共仓库。
6. 不发布临时脚本、凭据、缓存或范围外的未跟踪产物。

## 授权边界

- 本需求不授权也不要求改写 Git 历史、删除旧提交或改变现有提交哈希。
- 本需求授权设置本仓库后续提交使用的隐私邮箱、清理当前版本中的绝对路径、添加许可证相关
  文件和提交、设置指定远程并首次推送 `main`。
- GitHub 网页上的公共仓库创建由用户在最终确认后亲自点击；仓库不存在、非空或目标归属不一致时停止推送。
- 不创建发行版、标签、GitHub Actions、Issues、PR、Pages、额外分支或组织设置。
- 不修改 GitHub 账号权限、邮箱设置或其他仓库。
- 不输出、复制或记录任何登录凭据。

## 验证与验收

- 发布准备前后的原有提交哈希保持不变，全部内部提交引用仍然有效。
- 本仓库 Git 配置中的后续提交邮箱为已确认的 GitHub 隐私邮箱，新发布提交的 author/committer
  均使用该邮箱。
- 当前版本扫描不再出现含本机用户名的用户目录或特定盘符仓库绝对路径；完整历史允许保留已知
  邮箱和旧路径。
- `git fsck` 通过，历史提交数量和拓扑未被改写；除前向路径清理与许可证发布改动外没有内容漂移。
- 根目录存在完整、标准的 Apache License 2.0 文本，README 明确链接或声明该许可证。
- 敏感信息复查未发现令牌、私钥、密码或其他不应公开的内容。
- GitHub 公共仓库存在且为空后才执行首次推送；推送完成后远程 `main` 与本地 `main` 指向同一提交。
- 最终工作区干净，`origin` 指向精确目标，公开仓库可读取 README 与许可证。

## 停止条件

出现以下任一情况时停止，不勉强发布：原有提交哈希发生意外变化；发现新的敏感信息；GitHub
目标仓库不是空仓库；认证失败；远程归属或仓库名与本需求不一致；推送需要扩大当前授权范围。
