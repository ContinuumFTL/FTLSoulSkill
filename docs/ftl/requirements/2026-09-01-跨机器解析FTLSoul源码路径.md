# 跨机器解析 FTLSoul 源码路径

## 目标

移除 FTLSoul Skill 中绑定当前机器的 `Z:\Code\FTLSoulSkill` 和 `C:\Users\Administrator` 路径规则，改为确定性解析每位用户自己的 FTLSoul 权威源码工作树。当前用户继续解析到现有 Z 盘仓库，其他用户可以从任意受支持路径克隆并安装，不因路径优化降低普通 Skill 调用性能或源码编辑可靠性。

## 已达成一致

- 当前机器和云端历史已经暴露的本机路径可以保留，不为隐私目的改写 Git 历史。
- 修改并验证新的路径规则、相关 Skill 和必要脚本；完成后创建本地提交并把本次新内容推送到 `https://github.com/ContinuumFTL/FTLSoulSkill.git` 的 `main`。
- `docs/` 恢复由主仓库跟踪并随 `main` 推送到公共 GitHub，使 Coding Agent 能从项目 Git 历史查询需求依据；不再维护本地提交但对公开远端隐藏文档的中间状态。
- 不通过扫描磁盘或猜测目录寻找源码，也不把用户安装目录、Codex Skill 目录或插件缓存当作可编辑源码。

## 路径规则

1. 新增确定性的源码根目录解析脚本，由 `ftl-skill-authoring` 调用；重复使用的路径判定不在模型提示中临时拼装。
2. 解析器优先验证脚本所在位置能够确定的仓库源码根目录；从受管全局安装链接调用时，读取与该安装根相邻的 `.ftl-soul-skill-links.json`，使用其中经过规范化的 `sourceRoot`。
3. 候选目录必须是 Git 工作树根目录，并包含 `AGENTS.md`、`README.md`、`scripts/link-skills.ps1`、`skills/` 和目标 `ftl-skill-authoring`；验证失败时不得作为源码使用。
4. 同时发现多个互相冲突的有效来源时停止并报告，不静默选择第一个来源。找不到有效来源时提示用户从实际克隆目录运行 `scripts/link-skills.ps1`，不扫描其他磁盘位置。
5. `ftl-router` 按 Skill 名称调用已经安装或当前仓库可发现的 `ftl-skill-authoring`，不再写死源码绝对路径。`ftl-skill-authoring` 的校验脚本和交付路径都从解析后的源码根目录生成。
6. `scripts/link-skills.ps1` 继续以自身所在仓库作为默认 `SourceRoot`，在受管清单中记录实际源码根目录；不改变普通 Skill 的全局发现目录和符号链接机制。

## 本机兼容性

- 当前受管清单的 `sourceRoot` 为 `Z:\Code\FTLSoulSkill`，新解析器在本机必须返回同一路径。
- 在本仓库中直接执行与从 `%USERPROFILE%\.agents\skills\ftl-skill-authoring` 受管链接执行都必须定位到同一 Git 根目录。
- 在用户现有全局安装中补齐缺失的 `ftl-skill-authoring` 和 `ftl-browser` 受管链接，并更新清单；只使用仓库已有的 `scripts/link-skills.ps1`，不手工复制 Skill。
- 普通路由、需求、简单改动、提交和其他 Skill 不执行源码根目录解析，不增加额外路径检查。

## 实施范围

- 修改 `skills/engineering/ftl-router/SKILL.md` 和 `skills/engineering/ftl-skill-authoring/SKILL.md` 中的硬编码路径规则。
- 在 `skills/engineering/ftl-skill-authoring/scripts/` 中新增或调整确定性路径解析脚本及直接相关验证。
- 更新 `README.md` 中绑定当前机器的源码路径说明。
- 仅在确有必要时调整 `scripts/link-skills.ps1`，保留现有安装清单和链接行为。
- 通过受管安装脚本同步当前用户缺失的全局 Skill 链接。
- 删除仅含 `/docs/` 的 `.gitignore`，把当前本地 `docs/` 全部恢复为主仓库跟踪内容并随本次更新推送。
- 不修改其他 Skill 的业务职责、任务路由、授权边界或生命周期。

## 验证与验收

- 路径解析器在当前 Z 盘源码调用、当前用户受管链接调用以及隔离的其他克隆路径场景中均返回对应仓库根目录。
- 清单缺失、签名文件缺失、Git 根目录不匹配和多个来源冲突场景均明确失败，不回退修改安装副本或缓存。
- `ftl-router` 和 `ftl-skill-authoring` 的当前版本不再包含特定用户名或 `Z:\Code\FTLSoulSkill` 硬编码。
- `skill-creator` 的 `quick_validate.py`、仓库 Markdown 校验、`scripts/link-skills.ps1 -WhatIf`、`git diff --check` 和相称的路径解析行为测试全部通过。
- 当前用户全局安装清单包含仓库内全部 FTLSoul Skill，受管链接目标指向当前 Z 盘源码；普通 Skill 的发现和调用方式保持不变。
- 最终 Git 工作区干净，本地 `main` 与远端 `main` 指向同一新提交，远端当前树包含本地现有的全部 `docs/`。

## 授权边界

- 用户已授权恢复主仓库对 `docs/` 的跟踪与公开推送，并授权实施新的路径规则、更新当前 Skill 内容，在验证完成后推送本次新内容到指定公共仓库。
- 不改写 Git 历史、不强制推送、不修改远端仓库设置、不创建分支、标签、PR、Release 或其他外部资源。
- 除通过受管安装脚本补齐当前用户 FTLSoul 链接及清单外，不修改其他用户配置、插件缓存或范围外文件。

## 停止条件

发现路径来源冲突无法确定权威源码、验证失败无法在当前范围内修复、远端 `main` 在推送前发生未知更新、需要改写历史或扩大外部写入范围时停止并报告。
