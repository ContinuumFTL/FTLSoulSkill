## 背景与目标

当前 FTLSoul 没有负责浏览器工具选择的独立 Skill。实际任务中，系统 Chrome、Edge、
Codex 内置浏览器和 CLI 自动打开的系统浏览器曾被重复或交替使用，造成控制通道超时、
页面状态分散、认证页重复打开，以及无法判断操作是否已经生效。

本次变更新增一个可自动匹配的独立 Skill：当任务需要实际打开、导航或操作网页界面时，
统一选择可靠的执行路径；能够由专用连接器、API 或 CLI 完成的语义操作不为使用浏览器而
使用浏览器，必须进行网页交互时默认使用 Codex 内置浏览器。

## 已明确的行为

### 1. 适用范围与默认路径

- Skill 名称使用 `ftl-browser`，位置为 `skills/productivity/ftl-browser/SKILL.md`。
- 当请求需要打开网页、读取交互式页面状态、点击、输入、导航、处理网页登录或设备授权时，
  由 `ftl-router` 路由到本 Skill。
- 普通互联网资料搜索、只读网页检索和无需页面交互即可完成的研究不触发本 Skill，继续使用
  适合的搜索或资料工具。
- 对仓库、账号、工单等资源的语义操作，存在可靠的专用连接器、API 或 CLI 时优先使用它们；
  只有任务确实依赖网页 UI 时才进入浏览器控制。

### 2. 浏览器选择

- 网页交互默认使用 Codex 内置浏览器及其专用控制能力。
- 不打开或控制 Chrome、Edge 或其他系统浏览器，除非用户在当前请求中明确指定它们。
- Codex 内置浏览器无法完成任务时，不静默切换系统浏览器；说明实际失败和可选路径，等待
  用户决定。
- 用户明确指定系统浏览器时遵循该选择，但不得把一次系统浏览器授权扩展为今后任务的默认
  偏好。

### 3. 防止重复页面和认证分流

- 同一任务、同一 URL 或同一认证流程只维持一条浏览器路径，不同时在系统浏览器和 Codex
  内置浏览器打开重复页面。
- CLI 的设备授权流程若允许手动打开授权 URL，则停在设备码步骤，只在 Codex 内置浏览器
  打开授权页，不触发 CLI 的“打开系统默认浏览器”动作。
- 若第三方程序无法抑制地自动打开了系统浏览器，不再同时打开 Codex 内置浏览器；明确把该
  页面交给用户手动完成，或在取得用户选择后终止外部流程并改走内置浏览器。
- 一次性设备码可以在当前授权交接中展示给用户，但不读取、索取或转述用户密码、邮箱验证码、
  会话 Cookie 或其他登录凭据。

### 4. 失败、切换与外部副作用

- 浏览器页面加载或控制调用超时后，先用同一浏览器的可见状态、标签页状态或目标资源的权威
  只读接口判断动作是否已经生效，避免因“超时但已执行”而重复点击。
- 切换浏览器属于执行路径变化，必须说明原因；涉及登录状态、验证码或危险操作时必须保留原有
  授权与确认边界。
- 本 Skill 只决定工具和交互路径，不授予创建、修改、发布、购买、发送消息、删除或其他外部
  副作用。具体动作仍需要来自用户请求或适用工作流的授权。
- 永久删除、提交、支付等不可逆或高风险动作仍在最后执行点进行相称确认，不能因为使用内置
  浏览器而省略。

## 修改范围

- 新增 `skills/productivity/ftl-browser/SKILL.md`，实现浏览器路径选择、认证交接、失败判断和
  授权边界。
- 修改 `skills/engineering/ftl-router/SKILL.md`，使实际网页交互请求能够路由到
  `ftl-browser`，同时保持普通搜索和非浏览器语义操作的原有路线。
- 修改 `README.md`，在 Skill 目录和调用说明中登记 `ftl-browser`。
- 不创建脚本、参考资料或资源目录；本 Skill 的规则足够短，应保持单一 `SKILL.md`。
- 不修改 Chrome、Edge、Codex、Windows 默认浏览器或任何浏览器扩展配置。
- 不安装或卸载浏览器插件，不迁移 Cookie、会话或凭据。

当前工作树中的既有 `README.md` 修改和未跟踪的 `skills/engineering/ftl-vscode-launch/` 不属于
本次需求。实施时只允许保留并精确合并与 `ftl-browser` 目录登记有关的 README 行，不得覆盖、
回滚或提交其他任务的改动。

## 验收预期

- `ftl-browser` 的名称、目录和 frontmatter 符合 Skill 规范，描述能够区分交互式浏览器任务、
  普通网络搜索和可由连接器/API/CLI 完成的语义操作。
- Skill 明确规定 Codex 内置浏览器为网页交互默认路径；未经当前请求明确指定，不使用
  Chrome、Edge 或其他系统浏览器。
- 内置浏览器失败时会停止并说明，不静默切换；不会为同一认证流程同时打开两个浏览器。
- CLI 设备授权、外部浏览器被强制打开、控制调用超时但动作可能已经生效等真实场景都有明确
  且不扩权的处理规则。
- `ftl-router` 能将需要实际网页交互的请求交给新 Skill，不误接管普通网络研究。
- README 的 Skill 目录与实际文件一致，并保留当前工作树中其他任务的改动。
- 新 Skill 和仓库内全部 Skill 均通过 `skill-creator/scripts/quick_validate.py`，
  `git diff --check` 通过。
