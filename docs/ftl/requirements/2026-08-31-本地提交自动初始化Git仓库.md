## 背景

当前 `ftl-local-commit` 在目标目录不是 Git 工作树时只报告无法提交。项目可能已经完成需求确认、实现和验证，直到创建检查点时才发现从未初始化仓库，导致此前工作无法形成可审查、可回退的提交历史。

## 目标

只在 `ftl-local-commit` 中补充 Git 仓库初始化约束。当上游已经提供提交目的、允许暂存路径和验证结果，但目标项目尚未初始化 Git 时，由提交 Skill 在安全确认项目根目录后先初始化仓库，并在具备安全初始基线后继续创建上游要求的业务提交。

## 范围

- 修改 `skills/engineering/ftl-local-commit/SKILL.md`。
- 不修改 `ftl-router`、`ftl-requirements`、`ftl-requirements-execution`、`ftl-simple-change` 或其他业务 Skill。
- 不新增脚本、参考文件或其他辅助资源。
- 不改变已有 Git 仓库中的暂存、验证和提交纪律。

## 规则

- 目标目录不是 Git 工作树时，先确认该目录是上游任务的预期项目根目录，并确认它不位于另一个 Git 工作树内；无法可靠确认时停止，不得猜测根目录或创建嵌套仓库。
- 根目录确认后初始化 Git 仓库，不配置远端，不执行 push，也不由初始化推导任何其他外部动作。
- 新仓库在创建业务提交前必须具有安全的初始基线。建立基线前检查忽略规则、候选文件、敏感信息、生成物和明显不应入库的本地数据。
- 初始基线是独立提交单元。若建立安全基线需要暂存上游尚未授权的路径，返回上游补充明确的基线目的、允许路径和验证条件；不得借初始化扩大当前业务提交范围。
- 无法安全确定基线内容、发现疑似敏感信息或项目规则禁止初始化时，保留现有文件并如实停止，不创建虚假或不完整的提交记录。
- 已经处于 Git 工作树且已有提交历史时，继续执行现有的隔离提交规则，不增加其他 Skill 的重复检查。

## 验收预期

- `ftl-local-commit` 明确包含上述初始化、根目录确认、安全基线和范围不足时停止的约束。
- 规则不会允许在错误子目录创建嵌套仓库，也不会允许把未授权文件自动纳入首个基线提交。
- 现有仓库的普通业务提交行为、精确暂存边界及禁止 push、合并和历史改写的规则保持不变。
- 通过 `skill-creator` 的 `quick_validate.py`、仓库 Markdown 校验、`scripts/link-skills.ps1 -WhatIf`、`git diff --check` 和精确差异审查。
