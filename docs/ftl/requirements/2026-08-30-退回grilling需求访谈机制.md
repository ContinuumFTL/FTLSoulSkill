## 背景与目标

当前 `ftl-requirements` 集成的原版 `grilling` 访谈机制实际使用体验不佳。本次变更希望退回该功能，但在实施前必须区分同期引入的其他路由和需求流程逻辑，避免把仍然需要的行为一并移除。

本需求直接关联已经执行完毕的历史基线：[以原版 grilling 替换需求讨论机制](2026-08-26-以原版grilling替换需求讨论机制.md)。历史文档仅用于审计，不作为本次变更的实施授权。

## 已查明的实现边界

原功能由三个连续提交引入：

- `495c391`：确认原版 `grilling` 集成需求，仅新增历史需求文档；
- `70edd25`：实现集成，修改路由、需求 Skill、README，并新增快照、许可证和换行属性；
- `b77b975`：把历史需求文档标记为执行完毕。

仓库没有把 `grill-me` 或 `grill-with-docs` 注册为独立 Skill。实际生效的是 `ftl-requirements` 内部引用的原版 `grilling` 快照。

实现提交 `70edd25` 同时包含两类变化：

1. **直接的 grilling 集成**
   - `ftl-requirements` 在关键需求未决时强制读取并使用 `references/grilling.md`；
   - 新增上游快照、MIT 许可证和 `.gitattributes` 换行规则；
   - README 增加快照来源、接入方式和流程图关系。
2. **同期的路由与需求语义重组**
   - 将顶层意图显式整理为“只读讨论、形成需求、明确实施”三条路线；
   - 强调普通讨论不会仅因出现计划、设计取舍或局部共识而自动进入需求流程；
   - 调整 `ftl-requirements` 的触发描述，明确其不用于普通只读讨论。

在 `70edd25` 之后，提交 `31d5d13` 和 `40f6bc8` 又修改了 README 和 `ftl-router`，加入 Codex 认证恢复逻辑。因此不能把旧提交区间直接机械反转；实施时需要按最终确认的语义做定向修改，并保留后续认证恢复能力。

## 已确认的变更边界

本次采用定向回退，不把当前分支或整个文件机械恢复到旧提交：

- 仅移除 `grill-me / grilling` 引入的访谈机制及其直接依赖；
- 受该机制影响的需求澄清行为由 `commitA`（`cf0712f`）中的原有行为接管，即使用 `ftl-requirements` 的普通澄清与逐项结算规则，不增加新的替代访谈算法；
- 不改变当前其他与 `grill-me / grilling` 无关的功能和规则；
- 保留“只读讨论、形成需求、明确实施”三条顶层路线；
- 保留普通讨论不会仅因出现计划、设计取舍或局部共识而自动进入需求流程的规则；
- 完整保留后续加入的 Codex 沙箱认证恢复 Skill、路由规则、README 说明和相关需求记录；
- 保留其他当前文件内容，只有为消除 `grill-me / grilling` 的活动依赖而必需的行允许修改。
